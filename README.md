# 中转助手（s-ui 一键中转）

粘贴落地 → 自动在 s-ui 里建好中转节点 → 出客户链接和二维码。

- 落地支持：`socks5://账号:密码@IP:端口`、`IP:端口:账号:密码`、`http://`、`vless://`、`vmess://`、`trojan://`、`hy2://`、`ss://`、`tuic://`、`anytls://`
- 直连节点：不用落地，客户直接走中转机自己的 IP 出网；每条直连线路单独计流量、设备和到期，以后可用「换落地」改成走落地（链接不变）
- 客户入站可选：VLESS-Reality（推荐）、Hysteria2、SOCKS5，可多选：同一落地一次生成多个协议节点
- 节点名自动生成：落地国家 + 客户名 + 落地 IP（可改）
- 同一落地的不同协议节点按组显示：续期、停用/启用、勾选都整组生效，续期时到期时间自动统一
- 流量监控与限额：每条线路（同一落地的几个协议合计）显示已用流量，可设流量上限，用完自动停用；续期时可清零
- 设备数限制：按客户 IP 统计每条线路的在线设备，满了以后新设备连不上（防火墙放行已在用的设备），旧设备断开约 3～4 分钟后释放名额；也可以点设备数查看在线 IP，手动踢出某个 IP（立刻断开并禁止一段时间）、解除禁止或全部释放名额
- 新建时如果落地已被其他线路用过会提示，可选择挂到原线路（加协议）、新建独立线路或跳过
- 线路管理：搜索、检测落地连通、原位换落地（客户链接不变，显示完整落地账号密码）、给已有线路加协议（共用同一落地）、续期、停用/启用、批量导出链接和二维码、删除
- 只通过 s-ui 自带接口操作，不改 s-ui 程序，s-ui 面板里照样能看到和修改这些节点

## 安装

在装有 s-ui 的中转服务器上（root）执行一行：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/katon4612-spec/relay-helper/main/install.sh)
```

升级也是同一行命令（保留原配置）。

安装时自动读取 s-ui 的端口、路径和管理员账号，只需要输入「中转机域名/IP」（客户链接里用的地址，例如 `yyus.liveshop.work`）。
装完会显示访问地址和登录密码。

**云服务器安全组**需要放行：
- 工具页面端口（安装完显示，默认 2097/TCP）
- 中转端口范围 10000-60000（TCP；用 Hysteria2 还要 UDP）

服务器自带的 ufw / firewalld 会自动放行，不用手动加。

## 使用

1. 「一键中转」：填客户名、选入站协议和到期时间，粘贴落地（每行一条）→ 解析预览 → 检测落地 → 创建
2. 创建完成后可以复制全部链接、下载全部二维码（文件名就是节点名）
3. 「线路管理」：按客户名/IP 搜索，勾选后可批量检测、续期、停用、导出、删除

## 安全与运维

- **HTTPS**：安装/升级时会询问是否启用。中转机地址是域名、且 80 端口空闲时，自动用 acme.sh 申请 Let's Encrypt 证书并自动续签（需要云安全组放行 TCP 80）；否则使用自签名证书（同样加密，浏览器首次打开点「继续访问」）。之后单独重新配置：`bash /opt/relay-helper/https.sh /opt/relay-helper force`
- **Telegram 通知**：在「设置」页填 Bot Token 和 Chat ID，可发送测试消息。
- **落地自动巡检**：默认每 5 分钟检测所有在用线路的落地，连续 2 次不通发 Telegram 告警，恢复后通知；「线路管理」检测列显示最新结果。
- **自动备份**：默认每天 4 点备份 s-ui 数据库、限额记录和工具配置，保留 14 份（`/opt/relay-helper/backups`），可同时发到 Telegram 异地保存；「备份」页可手动备份、下载、恢复（恢复前自动备份当前状态，不会恢复工具自己的登录配置）。

## 需要知道的

- **创建和删除会重启一次 s-ui**（约 3 秒断线）：s-ui 改路由规则必须重启内核，而 s-ui 1.3.10 在面板里直接重启内核时，有 Hysteria2 节点就可能出现 `address already in use`，导致所有节点掉线。工具改为直接重启 s-ui 服务，每次都能干净恢复。批量创建/删除只重启一次。
- 换落地、续期、停用/启用 **不会**重启，不影响其他线路。
- 重启后内核没起来会自动再重启（最多 3 次）。工具还会把所有节点端口加入系统保留端口（`/etc/sysctl.d/99-relay-helper.conf`），避免重启那一刻端口被往外的连接临时占用导致内核启动失败；不需要可在配置里设 `"reserve_ports": false`。
- 落地国家通过 ip-api.com 查询（会把落地 IP 发给这个免费服务）。不想用可以在配置里设 `"geo_lookup": false`。
- 默认是 HTTP 访问。如果 s-ui 面板配置了证书，工具会自动用同一张证书开 HTTPS。

## 安全：停用/过期节点不会变成公开代理

s-ui 在用户停用或过期后会清空入站用户，SOCKS5 入站此时会变成免密码，连接匹配不上落地规则就会从中转机直接出网。
中转助手给每个节点都加了一条兜底规则：没匹配上落地的连接一律拒绝。老版本建的节点或在 s-ui 面板里手动建的中转节点，
打开「线路管理」时页面顶部会提示，点「一键修复」即可补上（只补「所有用户都走落地」的中转入站，不动其他入站）。

## 流量和设备数是怎么统计的

- 流量：读取 s-ui 自带的用户流量统计（每 10 秒更新），同一落地的几个协议节点相加。需要 s-ui「流量统计」开启（默认开启）。
- 设备：VLESS / SOCKS5 从系统连接表读客户 IP；Hysteria2 走 UDP，从 s-ui 的连接日志里读客户 IP，需要 s-ui 日志级别为 info（默认就是）。
- 设备数满了以后，工具用一条专用的 iptables 链 `RELAYHELPER` 只放行已在用的 IP，不改动系统原有的防火墙规则。
- 设备按 IP 算：同一个网络下的多台电脑（例如同一台电脑上的多个指纹浏览器环境）算 1 台。

## 配置文件

`/opt/relay-helper/config.json`，改完执行 `systemctl restart relay-helper`。

| 项 | 说明 |
|---|---|
| `port` / `path` / `password` | 工具页面端口、访问路径、登录密码 |
| `public_host` | 客户链接里的服务器地址 |
| `sui_url` / `sui_user` / `sui_pass` | s-ui 地址和管理员账号 |
| `port_min` / `port_max` | 新中转端口的随机范围 |
| `check_url` | 检测落地时访问的网址 |
| `geo_lookup` | 是否自动查落地国家 |
| `auto_firewall` | 是否自动在 ufw/firewalld 放行新端口 |

## 升级 / 卸载

- 升级：重新执行上面的安装命令（保留原配置）
- 卸载：`bash /opt/relay-helper/install.sh uninstall`（已建的线路不受影响）
- 日志：`journalctl -u relay-helper -f`
