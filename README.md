# 中转助手（s-ui 一键中转）

粘贴落地 → 自动在 s-ui 里建好中转节点 → 出客户链接和二维码。

- 落地支持：`socks5://账号:密码@IP:端口`、`IP:端口:账号:密码`、`http://`、`vless://`、`vmess://`、`trojan://`、`hy2://`、`ss://`、`tuic://`、`anytls://`
- 直连节点：不用落地，客户直接走中转机自己的 IP 出网；每条直连线路单独计流量、设备和到期，以后可用「换落地」改成走落地（链接不变）
- 客户入站可选：VLESS-Reality（推荐）、Hysteria2、SOCKS5，可多选：同一落地一次生成多个协议节点
- 节点名自动生成：落地国家 + 客户名 + 落地 IP（可改）
- 同一落地的不同协议节点按组显示：续期、停用/启用、勾选都整组生效，续期时到期时间自动统一
- 流量监控与限额：每条线路（同一落地的几个协议合计）显示已用流量，可设流量上限，用完自动停用；续期时可清零
- 设备数限制：按客户 IP 统计每条线路的在线设备，满了以后新设备连不上（防火墙放行已在用的设备），旧设备断开约 3～4 分钟后释放名额；也可以点设备数查看在线 IP，手动踢出某个 IP（立刻断开并禁止一段时间）、解除禁止或全部释放名额
- 新建时如果落地已被其他线路用过会提示，可选择挂到原线路（加协议）、新建独立线路或跳过
- 线路管理：搜索、检测落地连通、原位换落地（客户链接不变，显示完整落地账号密码）、给已有线路加协议（共用同一落地）、续期、停用/启用、批量导出链接和二维码、删除
- 只通过 s-ui 自带接口操作，不改 s-ui 程序，s-ui 面板里照样能看到和修改这些节点

## 安装

在装有 s-ui 的中转服务器上（root）执行一行：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/katon4612-spec/relay-helper/main/install.sh)
```

升级也是同一行命令（保留原配置）。

安装时自动读取 s-ui 的端口、路径和管理员账号，只需要输入「中转机域名/IP」（客户链接里用的地址，例如 `yyus.liveshop.work`）。
装完会显示访问地址和登录密码。

**云服务器安全组**需要放行：
- 工具页面端口（安装完显示，默认 2097/TCP）
- 中转端口范围 10000-60000（TCP；用 Hysteria2 还要 UDP）

服务器自带的 ufw / firewalld 会自动放行，不用手动加。

## 使用

1. 「一键中转」：填客户名、选入站协议和到期时间，粘贴落地（每行一条）→ 解析预览 → 检测落地 → 创建
2. 创建完成后可以复制全部链接、下载全部二维码（文件名就是节点名）
3. 「线路管理」：按客户名/IP 搜索，勾选后可批量检测、续期、停用、导出、删除

## 双中转（给部分客户用）

在主控（添加了其他服务器的那台）「一键中转」解析预览后，勾选「双中转」里的其他中转，同一个落地会在当前服务器和勾选的服务器上各建一组节点，组成一条双中转线路：

- 客户的订阅里同时有几台中转的节点，名字后面带「·中转名」。v2rayN / Shadowrocket 里一个连不上就点另一台的；Clash 订阅自带「自动切换」组，不通自动换。
- 几台服务器的订阅地址内容一样（同一个令牌），发给客户一个即可；那台服务器挂了，换另一台的订阅地址。
- 在主控面板里对其中一台操作，会自动同步到另一台：续期、停用/启用、删除、换落地（含从落地库换）、限额、清零流量、自动换开关、加协议。换端口、换链接域名只改那一台，订阅里的节点会自动更新。
- 备用落地的设置、手动主/备切换也会同步。
- 各台服务器在后台自己换了落地（落地库自动换、备用落地自动切换、直接在那台面板上换），主控每 20 秒对一次：同一组里落地不一样了，就让其他台跟上**最新换的那台**（有备用落地的用主/备切换，否则原位换落地），并发 Telegram 通知。保证几台用的是同一个落地 IP。
- 另一台暂时连不上时，操作先记下来，每分钟自动重试，「线路管理」顶部会提示。
- 设备数、流量每台各算各的。同步只在主控面板上操作时发生（直接打开另一台的面板操作不会同步）。
- 「订阅」里可以「解除双中转」，两边线路都保留，不再同步。

## 安全与运维

- **HTTPS**：安装/升级时会询问是否启用。中转机地址是域名、且 80 端口空闲时，自动用 acme.sh 申请 Let's Encrypt 证书并自动续签（需要云安全组放行 TCP 80）；否则使用自签名证书（同样加密，浏览器首次打开点「继续访问」）。之后单独重新配置：`bash /opt/relay-helper/https.sh /opt/relay-helper force`
- **Telegram 通知**：在「设置」页填 Bot Token 和 Chat ID，可发送测试消息。
- **落地自动巡检**：默认每 5 分钟检测所有在用线路的落地，连续 2 次不通发 Telegram 告警，恢复后通知；「线路管理」检测列显示最新结果。
- **备用落地 / 自动切换**：「线路管理」每条线路点「备用落地」填一个备用落地。每 30 秒检测一次，主落地连续 2 次不通就自动切到备用（约 1 分钟内），主落地连续 3 次正常再自动切回（可关）；主备都不通时发告警。切换只换出站内容、出站 tag 不变，所以客户链接、二维码、流量统计、设备限额都不变，Telegram 会通知每次切换。也可手动切换。参数（config.json）：`failover_interval_sec`（默认 30）、`failover_fail_times`（2）、`failover_back_times`（3）。
- **VLESS-443 共用**：建线路或「加协议」时可选「VLESS-443 共用」。所有选这个协议的客户共用服务器的一个 443 端口（VLESS-Reality，看起来就是普通 HTTPS），按用户分流到各自的落地，不占新端口，客户之间互不影响（停用/删除/换落地/备用落地/流量限额都按客户单独生效）。设备数统计和限制同样按客户生效：工具会在 s-ui 配置里自动开启 sing-box 的 Clash API（只监听 127.0.0.1，带随机密钥），按每条连接的来源 IP 和所走线路区分客户；超出设备数的新设备和被踢的 IP 会在共用端口上被单独拒绝，不影响其他客户（同一出口 IP 也被别的客户正常使用时只断开这条线路的连接）。共用节点不能单独换端口。443 已被别的节点占用时会提示先用「换端口」把它挪开。端口可在 config.json 用 `shared_port` 修改（默认 443）。
- **换端口**：客户当地封了端口时，在「线路管理」点节点的「换端口」（可指定端口或随机），或勾选多条点「批量换端口」。落地、到期、流量、限额都不变，只是端口变了：旧链接失效，弹窗直接给出新链接和二维码（可复制全部、下载全部二维码）发给客户。系统防火墙自动放行新端口，云安全组需自己放行。
- **落地库**：「落地库」页批量导入买来的落地（自动识别国家和网段，可填供应商、进价、落地到期），一键检测；按国家/状态筛选，看哪些空闲、被哪条线路使用、哪些不通、哪些快到期。建线路时「从落地库选」；线路落地坏了，在「换落地」里「自动挑一个能通的换上」（只在同国家里挑，同网段优先，再看最近检测能通、在用线路少的；换之前先检测），或指定一个换；还可以给线路开「落地不通时自动从库里换」（线路管理里勾选多条可「开自动换 / 关自动换」，一键中转可勾「新线路开启自动换落地」）：每 60 秒检测，连续 2 次不通自动换，Telegram 通知。都是原位换出站，客户链接、订阅、限额不变。一键中转新建线路时，用到的新落地会自动加入落地库（重复的不加，可在页面上取消勾选「新落地自动加入落地库」）；「换落地」粘贴的新落地也会自动入库。「导出」可以复制/下载 .txt（每行一个落地），或下载带国家、供应商、进价、到期、备注的 .json，在另一台「导入落地」里选文件导入；添加了其他服务器时还能直接「复制到另一台中转」。参数：`pool_interval_sec`（60）、`pool_fail_times`（2）。
- **订阅链接（按线路）**：「线路管理」每条线路点「订阅」，得到这条线路所有协议节点的订阅链接和二维码。v2rayN / Shadowrocket 用标准订阅，Clash Verge / Mihomo 自动识别成 Clash 配置（也可用 `?format=clash` 链接）。客户导入一次，以后换端口、换落地、加协议，更新订阅即可；停用、过期的节点不会出现在订阅里；订阅里带流量和到期信息。链接泄露可以重置。备份恢复会带上订阅链接。
- **多服务器统一管理**：每台服务器照常装中转助手。在其中一台（主控）的「服务器」页添加其他服务器的地址和连接密钥（在对方「服务器」页复制）。顶部下拉框切换要管理的服务器，所有操作（含备份下载/恢复）都由主控转发；「服务器」页显示每台的在线状态、线路数、7 天内到期、已过期、落地不通，并能在所有服务器里搜客户。连接密钥等于那台服务器的管理权限，泄露了可以重置。
- **登录**：用 s-ui 面板的账号密码登录（每次登录都向 s-ui 验证，在 s-ui 里改了密码这里自动跟着变）。s-ui 连不上时，账号留空、用安装时显示的备用密码登录（也在 /opt/relay-helper/config.json 的 password）。
- **更换链接域名**：「设置」页最下方。换服务器/换域名后填入解析到本机的新域名，工具会先确认这个域名确实访问到本机，再一起修改 s-ui 的面板/订阅域名（如果设置过）、中转助手自己的地址，并让 s-ui 用新域名重新生成所有用户的链接和二维码；之后在「线路管理」全选「导出链接」发给客户。有的云服务器从本机访问不到自己的公网地址，检查不通过时可以确认后强制更换。
- **备份与恢复**（和 s-ui 自带的一样）：「备份」页点「下载备份」现做一份发给浏览器（服务器上不留文件），包含 s-ui 全部节点/用户/到期/已用流量/路由、用到的证书文件、中转助手的限额和 Telegram/巡检设置，一般几十 KB（可勾选包含流量统计历史）；「恢复备份」上传文件即可，也支持 s-ui 面板自己下载的 .db。恢复后自动接上 s-ui 新的端口/账号、放行防火墙端口；恢复前的状态自动存为 `/opt/relay-helper/before-restore.tar.gz`。
- **换中转服务器**：旧机「下载备份」→ 域名解析到新机 IP → 新机装 s-ui + 中转助手 → 新机「恢复备份」→ 安全组放行节点端口。

## 需要知道的

- **创建和删除会重启一次 s-ui**（约 3 秒断线）：s-ui 改路由规则必须重启内核，而 s-ui 1.3.10 在面板里直接重启内核时，有 Hysteria2 节点就可能出现 `address already in use`，导致所有节点掉线。工具改为直接重启 s-ui 服务，每次都能干净恢复。批量创建/删除只重启一次。
- 换落地、续期、停用/启用 **不会**重启，不影响其他线路。
- 重启后内核没起来会自动再重启（最多 3 次）。工具还会把所有节点端口加入系统保留端口（`/etc/sysctl.d/99-relay-helper.conf`），避免重启那一刻端口被往外的连接临时占用导致内核启动失败；不需要可在配置里设 `"reserve_ports": false`。
- 落地国家通过 ip-api.com 查询（会把落地 IP 发给这个免费服务）。这个免费接口每分钟限 15 次批量查询（每次 100 个 IP），一次导入很多落地时超出部分会在后台排队慢慢查；落地库里国家为空的每 30 分钟自动补一次，也可以选中后点「重新识别国家」。查询库里没有的 IP 用「编辑」手动填国家。不想用可以在配置里设 `"geo_lookup": false`。
- 默认是 HTTP 访问。如果 s-ui 面板配置了证书，工具会自动用同一张证书开 HTTPS。

## 安全：停用/过期节点不会变成公开代理

s-ui 在用户停用或过期后会清空入站用户，SOCKS5 入站此时会变成免密码，连接匹配不上落地规则就会从中转机直接出网。
中转助手给每个节点都加了一条兜底规则：没匹配上落地的连接一律拒绝。老版本建的节点或在 s-ui 面板里手动建的中转节点，
打开「线路管理」时页面顶部会提示，点「一键修复」即可补上（只补「所有用户都走落地」的中转入站，不动其他入站）。

## 流量和设备数是怎么统计的

- 流量：读取 s-ui 自带的用户流量统计（每 10 秒更新），同一落地的几个协议节点相加。需要 s-ui「流量统计」开启（默认开启）。
- 设备：VLESS / SOCKS5 从系统连接表读客户 IP；Hysteria2 走 UDP，从 s-ui 的连接日志里读客户 IP，需要 s-ui 日志级别为 info（默认就是）。
- 设备数满了以后，工具用一条专用的 iptables 链 `RELAYHELPER` 只放行已在用的 IP，不改动系统原有的防火墙规则。
- 设备按 IP 算：同一个网络下的多台电脑（例如同一台电脑上的多个指纹浏览器环境）算 1 台。

## 配置文件

`/opt/relay-helper/config.json`，改完执行 `systemctl restart relay-helper`。

| 项 | 说明 |
|---|---|
| `port` / `path` / `password` | 工具页面端口、访问路径、登录密码 |
| `public_host` | 客户链接里的服务器地址 |
| `sui_url` / `sui_user` / `sui_pass` | s-ui 地址和管理员账号 |
| `port_min` / `port_max` | 新中转端口的随机范围 |
| `check_url` | 检测落地时访问的网址 |
| `geo_lookup` | 是否自动查落地国家 |
| `auto_firewall` | 是否自动在 ufw/firewalld 放行新端口 |

## 升级 / 卸载

- 升级：重新执行上面的安装命令（保留原配置）
- 卸载：`bash /opt/relay-helper/install.sh uninstall`（已建的线路不受影响）
- 日志：`journalctl -u relay-helper -f`
